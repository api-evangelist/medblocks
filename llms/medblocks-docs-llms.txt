## API Reference
Explore the Medblocks Platform API generated from the oRPC OpenAPI specification.
URL: /docs/reference/api
## Create a patient
Create a patient with your own patient_id plus optional email, name, and metadata. The id is unique within your organization.
URL: /docs/reference/api/create-patient
## Register a webhook endpoint
Register an HTTPS endpoint to receive signed event deliveries. The signing secret is returned once in this response.
URL: /docs/reference/api/create-webhook
## Delete a patient
Permanently delete a patient and their connections by patient_id. Returns a tombstone confirming the deletion.
URL: /docs/reference/api/delete-patient
## Delete a webhook endpoint
Permanently delete a webhook endpoint and its delivery history. Returns a tombstone confirming the deletion.
URL: /docs/reference/api/delete-webhook
## Disconnect a connection
Revoke your organization's access to one of the patient's connections by its conn_ id. The patient's link to the source EHR is removed for your organization; stored tokens are revoked when no other workspace still uses them. Returns a tombstone confirming the disconnect.
URL: /docs/reference/api/disconnect-patient-connection
## Retrieve a FHIR source
Retrieve a single EHR from the catalog by its fhirsrc_ id or raw fhir_base_url, scoped to your environment.
URL: /docs/reference/api/get-fhir-source
## Retrieve a patient
Retrieve a patient by their patient_id - the developer-provided identifier set on creation.
URL: /docs/reference/api/get-patient
## Get patient records
Return the patient's latest stored FHIR resources with their source EHR, paginated.
URL: /docs/reference/api/get-patient-records
## Retrieve a webhook endpoint
Retrieve a single webhook endpoint by its wh_ id, including its URL, subscribed events, and status. The secret is never returned.
URL: /docs/reference/api/get-webhook
## Liveness check
Unauthenticated probe that returns ok and the current server_time to confirm the API is reachable.
URL: /docs/reference/api/health
## Start a patient session
Start a patient session and get back a url to send the patient to so they can connect their records. Track progress with the session's status.
URL: /docs/reference/api/init-patient-session
## List FHIR sources
Search the catalog of registered EHRs with cursor pagination and optional q text and vendor type filters.
URL: /docs/reference/api/list-fhir-sources
## List patient sessions for a patient
List a patient's sessions with cursor pagination and an optional status filter, identified by their patient_id.
URL: /docs/reference/api/list-patient-sessions-for-patient
## List patients
List your organization's patients with cursor pagination and optional exact-match filters on patient_id or email.
URL: /docs/reference/api/list-patients
## List recent webhook events for an endpoint
List recent delivery records for one endpoint with cursor pagination and an optional delivered filter for the delivery audit.
URL: /docs/reference/api/list-webhook-events
## List webhook endpoints
List your organization's webhook endpoints with cursor pagination and an optional status filter. Secrets are never returned.
URL: /docs/reference/api/list-webhooks
## Manually redeliver a webhook event
Re-enqueue a webhook event for delivery by its evt_ id. Limited to one redelivery per event each minute.
URL: /docs/reference/api/redeliver-webhook-event
## Retrieve an EHR launch context
Resolve the mb_launch handle (appended to your app's launch URL after an EHR launch) into the patient / encounter / practitioner / EHR the app was launched in.
URL: /docs/reference/api/retrieve-launch-context
## Retrieve a patient session
Retrieve a patient session by its ps_ id, including its current status and the connections created during it.
URL: /docs/reference/api/retrieve-patient-session
## Rotate the signing secret for a webhook endpoint
Generate a new signing secret for a webhook endpoint, invalidating the old one. The new secret is returned once in this response.
URL: /docs/reference/api/rotate-webhook-secret
## Update a patient
Update a patient by id. Omitted optional fields are cleared. patient_id in the body must match the URL.
URL: /docs/reference/api/update-patient
